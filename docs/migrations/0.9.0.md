# 0.9.0 scene 迁移说明

`0.9.0` 将 `tuiScenes` 的 scene descriptor 从 React 组件迁移为 imperative
pi-tui factory。这是只影响 scene 插件的破坏性变更；`ctx.tuiScenes` 的
`register/open/close` 控制面、owner 隔离、效果台账和 `subscribe` 语义保持不变。

## 新 descriptor

唯一支持的版本是 `dsh-tui/pi-tui-scene@1`：

```ts
import type {
  Component,
  TuiSceneContext,
  TuiSceneDescriptor,
} from '@deepseek-harness-tui/dsh-tui/scenes'

const scene: TuiSceneDescriptor = {
  version: 'dsh-tui/pi-tui-scene@1',
  id: 'my-dashboard',
  title: 'My dashboard',
  create(context: TuiSceneContext): Component {
    return new Dashboard(context)
  },
}
```

`create(context)` 必须返回 pi-tui 的 `Component`（至少实现
`render(width): string[]` 与 `invalidate()`）。scene context 只包含：

- bounded readonly `viewModel` snapshot；
- `src/tui/commands.ts` 的 typed `commands` sink；
- 宿主提供的 readonly `root` / `overlay` descriptors；
- 当前 scene 生命周期的 `AbortSignal`。

context 不包含 React、旧 `ui` kit、Channel、Cordis、Agent、Terminal、stdin 或
stdout。scene 不得创建第二个 TUI、Terminal、输入监听器或 render loop。

## 注册、打开和关闭

注册和打开仍然是原来的控制面：

```ts
ctx.inject(['tuiScenes'], (sceneCtx) => {
  const dispose = sceneCtx.tuiScenes.register(scene)
  ctx.effect(() => () => dispose())
})

// 插件自己的 command handler 中：
sceneCtx.tuiScenes.open('my-dashboard')

// scene Component 或插件生命周期中：
sceneCtx.tuiScenes.close()
```

插件必须继续保留 disposer，并让它绑定到自己的 activation。其它 activation
不能读取、打开、关闭或订阅该 scene。

## 拒绝和失败语义

- 旧的 `{ id, component }` descriptor、缺少 `version` 或未知版本会 fail closed，
  并抛出包含迁移原因的明确错误；不会推断版本，也不会 fallback 到 React。
- `create(context)` 抛错或返回非 `Component` 时，宿主关闭 scene、清空 active 并
  通过 typed notification sink 报告错误。失败实例不会进入新的 active scene。
- scene 的 render/input 异常必须留在 scene 边界内；不要让异常穿透唯一的 TUI/
  Terminal owner。

## JSX runtime

scene 不再使用 React，因此 scene 插件不应再设置
`jsxImportSource: '@deepseek-harness-tui/dsh-tui'`。根 `./jsx-runtime` 导出已删除，
插件和构建配置不应再引用该子路径；旧 React/JSX 文件在仓库中仍保留给尚未删除的
旧 UI 路径，不代表 scene 仍受支持。
